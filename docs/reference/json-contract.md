# Общий контракт входного JSON

Каждый файл начинается с `"schema_version": 1`. Разрешены только корневые массивы `categories`, `tags`, `attributes`, `products`; неизвестное поле — ошибка валидации. Внутри каждого объекта также запрещены неизвестные поля.

```json
{
  "schema_version": 1,
  "categories": [],
  "tags": [],
  "attributes": [],
  "products": []
}
```

`sku` товаров и `slug` справочников не должны повторяться в своём массиве. Описание конкретного массива: [товары](products.md), [категории](categories.md), [метки](tags.md), [атрибуты](attributes.md).

## Семантика переданных полей

- У товара отсутствующее поле не изменяется.
- Переданный пустой `categories`, `tags` или `attributes` у товара очищает только это поле.
- Явный режим `merge` добавляет переданные элементы к текущим; режим по умолчанию `replace` заменяет набор.
- Отсутствующее поле и явный `null` имеют разные канонические документы и SHA-256. Используйте `null` только для поля, схема которого его допускает.
- Локальный атрибут товара имеет `scope: "local"` без `slug`; глобальный — `scope: "global"` со `slug`.
- Корневые массивы справочников обрабатываются независимо от товаров.
- Справочник, упомянутый только у нового товара, не создаётся, если запуск без `--create-products` пропускает этот SKU.
- Поле `images` запрещено и не экспортируется. Изображения не поддерживаются до отдельного контракта дедупликации.

Вариации, заказы, автоматический откат и интеграция с Ozon не входят в поддерживаемый контракт. Явное удаление описано в [deletion.md](deletion.md).
